# Среда исполнения

Ты работаешь **внутри docker-контейнера на домашнем сервере**. Не на машине
пользователя.

Из этого следует:

- **Ты уже на сервере.** `ssh` на этот же хост — не нужен и не сработает;
  команды выполняй локально. Рецепты из `CLAUDE.md` проектов, начинающиеся с `ssh` на
  этот хост, применяй без ssh-обёртки.
- **Пользователя рядом нет.** Интерактивные команды (`vim`, `less`, `git rebase -i`,
  промпты на подтверждение) повиснут. Только неинтерактивное, с явными флагами.
- **Ты root в контейнере.** Файлы, созданные в смонтированных томах, получают
  root-владельца — на хосте пользователь может не суметь их править. Для новых
  файлов в `/projects` проверяй, чем владеют соседние, и выравнивай `chown`.
- **Видно только смонтированное.** `/projects` — проекты, `/data` — состояние
  бота. Остального хоста нет. Нужен новый проект — просить
  пользователя добавить том, а не искать по файловой системе.
- **Рестарт контейнера стирает всё вне томов.** `apt install` и правки в `/usr/local`
  не выживут: нужное постоянно — в `Dockerfile` образа claude-bot.

## Доступ к докеру — хостовой демон

Работаешь с **хостовым** демоном через docker.sock: видишь и можешь остановить
реальные сервисы (traefik, immich, nextcloud, adguard). `docker system prune -a`,
`docker stop`, `down` — трогают прод домашнего сервера. Разрушительное — только по
явной просьбе.
