# Среда исполнения

Ты работаешь **внутри docker-контейнера** — песочницы одного проекта. Не на машине
пользователя. Рабочие репозитории в `/projects`, состояние бота в `/data`;
остальной файловой системы хоста нет. Нужен новый проект — просить
пользователя добавить том, а не искать по файловой системе.

Пользователя рядом нет: интерактивные команды (`vim`, `less`, `git rebase -i`,
промпты на подтверждение) повиснут. Только неинтерактивное, с явными флагами.

Ты root в контейнере. Файлы, созданные в смонтированных томах, получают
root-владельца — на хосте пользователь может не суметь их править. Для новых файлов
в `/projects` проверяй, чем владеют соседние, и выравнивай `chown`.

Рестарт контейнера стирает всё вне томов: `apt install` и правки в `/usr/local` не
выживут, нужное постоянно — в `Dockerfile` образа claude-bot.

## Скиллы

`/root/.claude/skills` не смонтирован — записанное прямо туда умрёт с рестартом.
Писать в источники, симлинки оттуда создаст `entrypoint`:

- `/opt/skills/project/<name>/SKILL.md` — скилл этого проекта;
- `/opt/skills/shared/<name>/SKILL.md` — общий, его читает и ассистент с хостовым
  docker, и он публикуется на GitHub: без внутренних адресов и без команд,
  разрушительных вне песочницы.

Сомневаешься — `project/`. Коммитить не нужно, правка сама попадёт в репозиторий.

## Докер — свой демон, ломать безопасно

`DOCKER_HOST=tcp://localhost:2375` — свой демон (dind). Хостовых контейнеров не
видно, образы отдельные, сервисы домашнего сервера отсюда недостижимы. Сетевой
namespace общий с dind, поэтому порты запущенных тобой контейнеров доступны на
`localhost` как обычно.

**Грабля bind-mount:** пути в `docker run -v` резолвит демон, не ты. `-v /tmp/x:/x`
смонтирует `/tmp/x` **демона**, а не твой. Работает только там, где путь совпадает в
обоих: `/projects` смонтирован в dind по тому же пути специально для этого.
