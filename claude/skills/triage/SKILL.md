# /triage <задача>

Отвечает на один вопрос: **надо ли эту задачу делать вообще**. Код не правит.

## 1. Собрать вход

Достань задачу тем способом, что есть в окружении: скилл/CLI трекера задач, по ссылке или текст от юзера.
Прочитай комментарии и то, на что тикет ссылается. Есть файл разбора той же задачи — прочитай, разбор мог быть начат.
Выпиши **наблюдаемое ожидание**: что автор считает правильным поведением и по какому сценарию. Ожидание не сформулировано («работает не так») — это первая находка, спроси автора.

## 2. Найти код

Определи компонент (ближайший `CLAUDE.md` важнее корневого) и пройди путь до места, где рождается наблюдаемое поведение: точка входа → логика → хранилище → запрос/схема.
Догадка о поведении запроса не заменяет прогон на реальных данных.

## 3. Вердикт

| Что нашёл | Вердикт | Что делать |
|---|---|---|
| Код правда работает неверно | **баг** | Показать строку-причину, дальше — планирование |
| Код работает верно, ожидание в тикете неверное | **ошибка постановки** | Отписать в тикет, ждать решения. Код не трогать |
| Описанное поведение не воспроизводится | **нет репро** | Уточнить шаги у автора |
| Задача не про этот компонент | **не тот компонент** | Сказать юзеру, предложить переназначить |
| Несколько претензий разной природы | **смешанный** | Разложить по пунктам, у каждого свой вердикт. Работа дальше — только по «багам» |

**«Смешанный» — норма для карточек от QA.** Тикет на три пункта регулярно содержит один настоящий баг, одно осознанное поведение и одну фичу. Не подгоняй под один вердикт: иначе половина работы либо потеряется, либо уедет в скоуп без обсуждения. Пункты «ошибка постановки» и «фича» обязательно попадают в границы (что **не** делаем) и потом в описание MR — иначе QA вернёт задачу, сверив с «Ожидаемым результатом».
**Вердикт обосновывай кодом**, а не пересказом тикета: какая строка даёт поведение и почему оно (не)корректно. Без этого вердикт не выдавай.
Расхождение осталось неясным — так и скажи, не додумывай: за «багом» регулярно стоит корректная логика и неверное ожидание, и наоборот.

## 4. Записать

Вердикт не «баг» — работы не будет, писать нечего: скажи юзеру и всё. «Смешанный» пишем, если хотя бы один пункт оказался багом.
«Баг» — итог в `## Вердикт разбора`: вердикт + ссылка на код + границы. Попутный рефакторинг — не в этот скоуп.

## Границы

Код не правишь — это разбор. Трекер трогай только по подтверждению: комментарий дёргает уведомления автору.
